# 블로그 자동발행 파이프라인 (포트폴리오 발췌본)

LLM을 활용해 블로그 글감 수집부터 초안 작성·품질 검문·색인 요청까지 무인으로 돌리는 개인 파이프라인의 일부다. 계정 리스크가 있는 발행부(브라우저 자동화)와 비밀값은 제외하고, 판단 로직·검문 로직·스케줄러만 코드로 공개한다.

## 구조도

```
소스 수집 (enrich)
   -> 초안 작성 (draft, LLM 1회)         [코드 비공개]
   -> 코드 검문 (verify, LLM 0회, 정규식 8종)
   -> 수정 (REVISE, LLM 최대 1회, 검문 걸린 것만)
   -> 발행 (네이버 / 티스토리 브라우저 자동화)   [코드 비공개, 계정 리스크]
   -> 색인 요청 (gsc_index, Search Console)
   -> 스케줄러 (company.py: 시도 기록 · 백오프 · 안정판 롤백 · 아침 보고)
```

## 공개 범위

- 공개: `enrich.py`(소스 정리), `llm.py`(LLM 호출·일일 상한), `verify.py`(코드 기반 검문), `gsc_index.py`(색인 요청), `cats.py`(카테고리 로테이션), `company.py`(스케줄러)
- 비공개(계정 리스크): 네이버·티스토리 발행 스크립트, 브라우저 자동화(CDP) 코드, 초안 생성 프롬프트 본체. 위 구조도의 "발행" 단계가 이에 해당하며, 실제로는 로그인된 크롬을 CDP로 조작해 에디터에 입력하는 방식이다. 계정 보호(로그인 세션·쿠키 취급)와 직결되어 코드는 올리지 않는다.

## 운영 수치

- 두 달간 약 320편 무인 발행
- 글 한 편당 LLM 호출 2회(초안 1 + 수정 1) — 검문(verify)은 LLM 0회, 정규식 기반 8종 체크(`verify.py`의 `code_checks`: 정의문·질문형 소제목·날짜 기준·반대 시나리오·원문 링크·해석 프레임 6종은 자동 수정 대상, 자체 차트·1차 자료 링크 2종은 로그만 남기고 통과)
- 하루 LLM 호출 상한 15회(`llm.py`의 `CLAUDE_DAILY_CAP`, 기본값 15) — 무한루프 방지용 방어선이지, 게이트가 아니다
- 스케줄러(`company.py`) 백오프 시간표: 2 / 4 / 8 / 16 / 24시간(`BACKOFF_H`) — 실패할수록 재시도 간격을 늘린다

## 설계 원칙

- 멈추지 않는다: 글 한 편의 품질 검사가 실패해도 그 글만 세어서 로그에 남기고 파이프라인 전체는 계속 돈다. 게이트로 전체를 세우지 않는다.
- 하루 호출 상한은 예외다: 위 원칙보다 우선하는 유일한 제동장치는 무한루프 방지용 일일 LLM 호출 상한이다. 초과하면 그날은 로그만 남기고 멈춘다.
- 실패가 반복되면 사람이 아니라 과거의 나를 믿는다: 코드가 최근에 바뀌었고 연속 실패가 나면, 마지막으로 정상 동작한 코드(안정판)로 자동 롤백한다. 롤백 후에도 죽으면 그때 사람을 부른다.

## 실행 안내

여기 코드는 참고용이며 그대로 실행할 수 없다. 발행부·인증·환경변수가 빠져 있고, 원래 리포에서 발췌한 파일이라 상호 의존 관계가 일부 생략되어 있다.
